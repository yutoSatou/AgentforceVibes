# フローの種別
フローの種別に関しては下記を参考にしてください。

## 1. ユーザー操作が必要なフロー（画面フロー系）
これらのフローは、情報の収集や表示を行い、ウィザード形式でユーザーをガイドします [1][2]。

| フロー種別 | 特徴・用途 | 主な配布方法・起動元 |
| :--- | :--- | :--- |
| **画面フロー** | ビジネスプロセスに従ってユーザーをガイドします。画面、ステップ、選択肢などが使用可能です [2]。 | Lightningページ、Webタブ、URL、ボタン、アクション、オーケストレーションなど [3]。 |
| **アクションケイデンスステップ画面フロー** | Sales Cloudのケイデンスステップから起動し、情報の収集や表示を行います [1]。 | アクションケイデンス [1]。 |
| **Checkout 画面フロー** | Commerce Cloudのチェックアウトプロセス（購入手続き）を実装します [4]。 | エクスペリエンスビルダー (チェックアウトコンポーネント) [4]。 |
| **連絡要求画面フロー** | 顧客が連絡先詳細を入力するセルフサービスフォームとして機能します [4]。 | 連絡要求ボタン、ページへの埋め込み [5]。 |
| **Field Service Mobile / Web フロー** | モバイルアプリでのデータ収集や、Webブラウザでの予定予約・変更に使用します [5][6]。 | Field Serviceアプリ、組み込み予定予約 [6]。 |
| **ユーザープロビジョニング画面フロー** | ユーザーアカウントを作成し、サードパーティサービス等にリンクさせます [7]。 | ユーザープロビジョニングウィザード [7]。 |
| **その他の画面フロー** | デジタルフォーム [8]、従業員サービスカタログ [8]、住宅ローン貸付申込 [9]、個人-オブジェクトリンク [10]、Scheduler予定 [11] など。 | 各種専用アプリケーションやコンポーネント。 |

## 2. レコードやスケジュールで自動起動するフロー（バックグラウンド）
これらはユーザーの操作を必要とせず、データベースの変更や時間経過をトリガーとしてバックグラウンドで実行されます [12][2]。

| フロー種別 | 起動タイミング・特徴 |
| :--- | :--- |
| **保存前のレコードトリガーフロー** | レコードの作成・更新後、**保存される前**に起動します。高速な項目更新に適しており、ループや割り当てなどが使用可能です [2]。 |
| **保存後のレコードトリガーフロー** | レコードの作成・更新による**保存後**、または削除時に起動します。関連レコードの更新などに使用されます [12]。 |
| **削除前のレコードトリガーフロー** | レコードが**削除される前**に起動します [13]。 |
| **スケジュールトリガーフロー** | 指定された時間と頻度で、レコードのバッチごとに起動します。画面操作はサポートされません [2]。 |
| **Data Cloud データ変更フロー** | Data Cloudのデータモデルオブジェクト等のレコードが変更され、条件を満たした時に起動します [8]。 |
| **保存後にレコードトリガーされる顧客ライフサイクルフロー** | 顧客ライフサイクルマップの保存後に起動し、関連レコードを変更します [7]。 |

## 3. 外部呼び出しやイベントで自動起動するフロー（バックグラウンド）
Apex、REST API、ボタン、または特定のシステムイベントから呼び出されて実行されます [14][15]。

| フロー種別 | 説明・起動元 |
| :--- | :--- |
| **自動起動フロー (トリガーなし)** | REST API、Apex、プロセス、ボタン等から呼び出されます。画面や選択肢は使用できません [14]。 |
| **プラットフォームイベントトリガー** | プラットフォームイベントメッセージを受信したときに起動します [9]。 |
| **イベント駆動型フロー** | 特定のイベントを受信したときに起動します (Starter/Marketing Cloud Growth等) [16]。 |
| **フォームトリガーフロー** | Web訪問者がマーケティングフォームを送信した際に起動します [6]。 |
| **セグメントトリガーフロー** | Data Cloudセグメントが有効化されたりスケジュールされたりした時に起動します [3]。 |
| **有効化トリガーフロー** | Data Cloudの有効化が公開されたときに起動します [14]。 |
| **外部システム変更トリガー** | サードパーティシステム（MuleSoft等）で変更が検知された場合に起動します [16]。 |
| **おすすめ戦略の自動起動フロー** | Einstein Next Best Action用のおすすめリストを作成し、ユーザーの応答に応じて起動します [12]。 |
| **その他の自動起動フロー** | 活動オブジェクト照合 [14]、ブロードキャスト [15]、カート非同期 [15]、ロイヤルティ管理 [9]、ルーティング [17]、プロンプトテンプレート [9]、管理コンテンツ [17] など。 |

## 4. オーケストレーションとプロセス
複数のステップ、複数のユーザー、または長期間にわたるプロセスを管理するための種別です [14][15]。

| 種別 | 説明 |
| :--- | :--- |
| **フローオーケストレーション** | 複数ステップ・複数ユーザーのプロセスを作成します。自動起動またはレコードトリガーで開始されます [14][15][13]。 |
| **評価の自動起動フロー** | オーケストレーションにおいて、ステップの開始条件や終了条件を評価するために使用されます [5]。 |
| **自動起動フロー承認プロセス** | 複数ステップの承認プロセスを作成します。Apexやボタン、レコード保存から呼び出されます [14][13]。 |
| **CMS ワークフローオーケストレーション** | CMSコンテンツの作成・編集・管理を行うプロセスです [4]。 |
| **プロセスビルダー (レガシー)** | レコード変更、カスタムイベント、他のプロセスから起動する、バックグラウンド実行されるプロセスです [8][17]。 |

---

### 理解のためのヒント
フロー種別の違いは、レストランの運営に例えることができます。

*   **画面フロー**は「ウェイター」です。客（ユーザー）と直接対話し、注文を取り（情報収集）、案内します。
*   **レコードトリガーフロー/自動起動フロー**は「キッチンのスタッフ」です。注文が入った（レコード作成）、または時間が来た（スケジュール）などの合図を受けて、裏で黙々と作業（データ処理）を行い、客と直接会話することはありません。
